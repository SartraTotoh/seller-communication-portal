3 · UI copy rules — how we write on screens (บังคับทั้ง 2 portal)

กฎแกน: สั้น · ง่าย · ภาษาอังกฤษ · ภาษาคน · คนอ่านปุ๊บเข้าใจปั๊บ
DO — เขียนแบบนี้ yes
▸ New Request (ไม่ใช่ "Create Communication Submission")
▸ Upload file — สั้น ตรงไปตรงมา
▸ Who needs it? — คำถามภาษาคน
▸ Send, Save, Cancel — 1 คำ รู้ทันที
▸ When is it due? — ภาษาที่คนอ่านเข้าใจ
DON'T — ห้ามแบบนี้ no
✕ ศัพท์ AI / เทคนิค: "prioritize by heuristic weighting"
✕ นักเทคนิคคุยกันเอง: "consume from data connector layer"
✕ ประโยคยาว: "Please ensure that you have selected the appropriate target segment"
✕ ตัวย่อที่คนนอกไม่รู้: "SLA", "ROI", "P0" — อธิบายถ้าจำเป็นจริง
✕ ศัพท์ AI: "Insights", "Smart", "Agent", "Pipeline"... เปลี่ยนเป็นคำคน
หลักง่าย ๆ: ถ้าเพื่อนที่ไม่ได้ทำงานระบบนี้อ่านแล้วต้องเข้าใจได้ภายใน 1 วินาที แปลว่าผ่าน — ข้อความทุกคำต้องตอบได้ว่า "ผู้ใช้ต้องทำอะไร / เห็นอะไร"

4 · Label sheet — แต่งคำใหม่ทั้ง 2 portal

แก้จากคำเทคนิค → คำคน (ใช้ 1 คำ–3 คำ, ภาษาอังกฤษ)
EDU — Menu ใหม่ common English
▸ Insights → Results (คนอ่านรู้ว่าดูผลงาน ไม่ใช่ "ข้อมูลเชิงลึก")
▸ Task Hub → Tasks (สั้น เดิมก็โอเค)
▸ Hours & Capacity → Hours (เหลือ 1 คำ)
▸ Content Sync → Content (sync = เทคนิค เอา "ช่วงเวลา" ออก)
▸ AI Inbox → Inbox (ห้ามโชว์ "AI")
▸ Approvals & Consent → Approvals
▸ Convert / Route → Send to (ภาษาคน)
COMM — Menu ใหม่ common English
▸ Command Center → Tools (ศูนย์ควบคุม = น่ากลัว → Tools)
▸ Score & Ranking → Priority (จัดลำดับ = คำเทคนิค → Priority)
▸ Content Hub → Content
▸ Smart Links → Links (Smart = AI smell)
▸ Operations → Advanced (Ops = เทคนิค → Advanced)
▸ API Center → Connections (API = เทคนิค → Connections สำหรับ owner/admin)
▸ Dashboard stays Dashboard · Requests · Campaigns · Calendar · Reports · Settings (ผ่านอยู่แล้ว)
การใช้งาน: เมื่อพัฒนาใหม่ ทุก label/ข้อความต้องผ่านกฎนี้ก่อนลงโค้ด — เขียนไว้ใน dev ว่าห้ามใช้คำในรายการ DON'T ข้างบน

3 · สรุปความลึก (depth summary)

ทั้ง 2 portal · เปรียบเทียบจำนวนคลิกลึกสุด
EDU — ลึกสุด L4 (หน้าแรก 1 ตี → Task Hub → เปิด ticket → action) · หมดจด modal กลางที่แชร์ทั้งระบบ
COMM — ลึกสุด L5 (Dashboard → Requests → เปิดคำขอ → แก้ → submit) · หน้าแรกเข้าถึงทุกโมดูลได้ใน 1–2 คลิก
การใช้งาน blueprint: แผ่นนี้คือ click-depth map สำหรับพัฒนา UX — กฎคือ L≤2 สำหรับ action หลัก และ L≤4 สำหรับ secondary อะไรที่ลึกเกิน L5 ต้องทบทวนโครงสร้าง
